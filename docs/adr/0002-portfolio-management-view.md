# ADR: 统一持仓管理视图

## 状态

已采纳，已实现第一版。

## 背景

FinBox 已在 `config.yaml` 的 `stocks[].positions` 中保存个股持仓明细，并在个股详情页中提供单只股票的持仓编辑能力。随着股票数量和标签维度增加，仅从自选树或单只股票详情进入持仓数据，无法有效回答以下问题：

- 当前所有股票的持仓金额如何排序。
- 某个标签集合中包含哪些持仓或 0 股观察标的。
- 单只股票相对于总投入的暴露比例是多少。
- 账户整体股票仓位是多少。
- 是否可以在一个界面中快速维护多只股票的持仓明细。

因此需要一个独立的持仓管理视图，而不是继续把全局持仓分析分散在个股详情中。

## 决策

FinBox 新增主工作区“持仓”视图，入口放在左侧 activity bar。该视图包含 0 股股票，并复用现有股票配置、标签、别名和行情数据，不新增第二套持仓存储模型。

持仓视图采用主编辑区全宽页面。进入该页面时，不渲染左侧 explorer 面板和右侧笔记侧栏；只保留 activity bar 与主编辑区。这是因为统一持仓表本身已经承担筛选、查询和编辑职能，再叠加左右侧栏会压缩表格宽度并降低横向指标比较效率。

第一版采用以下范围：

- 查询支持标签、股票名称、别名和代码。
- 标签过滤使用 OR 逻辑，界面文案表述为“标签包含任一”。
- 表格默认按当前市值形式的持仓金额降序排序。
- 支持按持仓金额、持仓占比、仓位、今日盈亏、累计盈亏、涨跌幅、股票名称排序。
- 无行情时，依赖行情的市值、占比和盈亏指标显示为 `--`，排序时置底。
- 多账户持仓在股票行下方以内联编辑器展开，主表按股票聚合展示。
- 持仓编辑复用既有 `updateStockPositions` IPC 和 `stocks[].positions` 持久化结构。
- 点击股票名称进入个股详情，用于继续维护别名、标签、笔记和图表分析。

## 指标口径

本次实现采用以下口径：

- 持仓金额：单股当前市值，即 `持仓股数 * 当前有效价格`。
- 成本金额：单股所有账户的 `shares * cost` 汇总。
- 持仓占比：`单股市值 / total_investment`。
- 单股仓位排序：与持仓占比使用同一数值口径，即 `单股市值 / total_investment`。
- 总仓位：页面摘要中的账户级指标，公式为 `全部股票市值 / total_investment`。

这里的 `total_investment` 是用户在账户配置中维护的总投入。现金仅作为摘要展示，不参与上述仓位分母。

## 后果

该设计避免把持仓管理扩展为新的数据源，降低迁移成本；同时使查询、排序和编辑集中在一个工作台界面。其代价是第一版没有提供批量编辑、别名/标签内联编辑和账户级分组统计。后续如需增加账户维度，应继续保持股票聚合为主视图，账户明细作为展开层或二级过滤维度。
